## How the pieces fit
| What | Where it is served / stored | Refresh |
|---|---|---|
| Per-page title/description/OG/noindex/canonical | `SeoMeta` (path without locale + locale) → `GET /v1/seo/meta` → `generateMetadata` | web fetch tags `seo`, `seo:<path>` (+ `product:<slug>`), dropped by `POST /api/revalidate` after each save |
| Verification codes | setting `seo.verification` → `/v1/settings/public` → layout `verification` | tag `settings` |
| Schema toggles | setting `seo.schema` → `/v1/seo/public` | tag `seo` |
| robots.txt | setting `seo.robots.custom` (null = generated default) → `/robots.txt` rewrite | per request (5 min HTTP cache) |
| Sitemaps | Redis `seo:sitemap:file:*`, status `seo:sitemap:status` → `/sitemap.xml`, `/sitemaps/<locale>-<type>.xml` | job `seo.sitemap.regenerate` daily 06:00 Tashkent, 60 s after publish/updates, A9 button, on a cache miss |
| IndexNow key | setting `seo.indexnow.key` (generated by migration/seed) → `/<key>.txt` | — |
| IndexNow pings | Redis set `seo:indexnow:pending` → job `seo.indexnow.flush` (60 s debounce) | IntegrationLog `indexnow` |
| Search queries | `SearchQueryDaily` | job `seo.queries.sync` 05:40 Tashkent (last 5 days), A9 "Hozir sinxronlash" |
| CWV field data | `Event` `web_vitals` (tracker) | live query (28 days) |
| CWV lab data | `PageSpeedRun` | on demand from A9 |

Revalidation failing (web down, wrong key) only logs a warning on the API (`WebRevalidate`): pages
still refresh at their ISR interval (30 s–5 min). Check: `WEB_INTERNAL_URL` (compose `http://web:3000`),
the same `WEB_REVALIDATE_SECRET` (≥ 32 chars) in api and web — in production a missing secret disables revalidation and 404 reporting (API logs `WEB_REVALIDATE_SECRET is not set` at boot) — and clocks within ±5 min. The 404 log is pruned daily (job `seo.notfound.prune`: older than 90 d with < 3 hits, beyond the top 5 000).

## Owner checklist (go-live)
1. **Verification**: A9 → Tasdiqlash kodlari: paste Google / Yandex / Bing `<meta>` tags (or the codes).
   Then verify the property in each console.
2. **Google Search Console API**: Google Cloud project → enable "Google Search Console API" → service
   account → JSON key. In Search Console → Settings → Users and permissions add the service account
   e-mail (Restricted is enough for read). Admin → Integratsiyalar → Google Search Console: paste the
   JSON and the property (`https://forest.uz/` for a URL-prefix property or `sc-domain:forest.uz`).
3. **Yandex Webmaster API**: create an OAuth app (oauth.yandex.ru) with Webmaster read access, get a
   token for the shop account; `hostId` is shown by `GET /v4/user/{user_id}/hosts` (e.g.
   `https:forest.uz:443`); `userId` may stay blank (read from `GET /v4/user`). Paste into Integratsiyalar →
   Yandex Webmaster.
4. **Sitemap**: submit `https://forest.uz/sitemap.xml` once in GSC and Yandex Webmaster (we don't
   call the submit APIs; both re-read it).
5. **IndexNow**: on by default; needs `APP_URL` = the public https domain. After go-live press
   "Barcha sahifalarni yuborish" once.
6. **PageSpeed Insights** (optional): API key from Google Cloud (PageSpeed Insights API) → Integratsiyalar →
   PageSpeed Insights (connect without a key uses the shared quota).

## Not verified (open questions 70–74 in docs/13)
- GSC: dates are PST; we store the provider's date as the day (no Tashkent shift). Quota per project
  (we make ≤ 1 request/day per 25 000 rows). Anonymised queries are not returned (totals in A9 are the
  sum of returned rows, so they can be lower than the GSC UI totals).
- Yandex Webmaster: whether `search-queries/popular` for a one-day window returns per-day values for
  every query (we request one day at a time), the real `limit` maximum (500 per the clients), token
  lifetime/refresh (OAuth tokens last ~1 year; reconnect when it expires) and whether `AVG_SHOW_POSITION`
  is impression-weighted.
- IndexNow: whether Yandex and Bing share submissions (we ping both explicitly); behaviour for
  removed URLs (we send archived product URLs too, as the protocol allows).
- PageSpeed: field data keys in `loadingExperience.metrics` are not used (we have our own field data).
